# porsche3d — 3D-гараж услуг

Исходник модуля. На сайт попадает только бандл `dist/js/porsche3d.bundle.js`
(`npm run bundle-3d`): three r180, GLTFLoader и декодер Meshopt внутри, importmap не нужен.
Страница грузит его **только** `import('./porsche3d.bundle.js')` из `dist/js/garage.js` по нажатию
«Открыть 3D-гараж» — `npm run check` падает на статическом импорте, `<script>`, preload/prefetch или ссылке на `.glb`.

- `index.js` — `mount()`: загрузка модели с прогрессом, отменой и тайм-аутом, материалы, камера,
  поворот и приближение рукой, отрисовка по требованию, `dispose()`.
- `views.js` — ракурсы и соответствие работ «Гаража услуг» ракурсам и эффектам.
- `room.js` — помещение, свет и окружение для отражений (всё рисуется на canvas). Единственный внешний файл — логотип клуба на стене (`assets/brand/Horizontal_Logo.svg`, тот же, что в шапке сайта, обычно из кэша): грузится вместе с моделью, без него гараж открывается всё равно (ждём не дольше 1,5 с). Надпись — участок цилиндра на 1 см ближе середин граней стены (стена — многогранник, на телефоне грань на 1,5 см ближе радиуса), прозрачность смешиванием: alphaTest на мелком экране съедал тонкие штрихи. Место (`LOGO`: 43°, середина 2,1 м) — над машиной в «Общем виде» и в стороне от линии крыши с низкой камеры «Оклейки».
- `interior.js` — кокпит из v1 (кодом и canvas-текстурами, без загрузок): виден через стёкла. Торпедо строится под настоящее лобовое стекло модели: `buildInterior` снимает карту стекла (`glassMap`) и передаёт её в `buildCockpit` как `glassV1(x, z)`; полка торпедо — сетка 48×12, передняя кромка повторяет кривую основания стекла (центр z≈.84 v1, стойки ≈.69), высота — стекло минус 4,5 см, с передним бортом вниз за кромку кузова (щели к капоту не видно). Текстура полки — тёмный винил с мелким зерном и щелями обдува (canvas без градиентов: check:3d собирает кокпит в Node с заглушкой холста). Над приборами — невысокий козырёк с тонким навесом, на стекле — салонное зеркало (ножку к стеклу подводит `fitUnderGlass`), под крышей — солнцезащитные козырьки целиком за верхней кромкой стекла (у стоек она уходит назад). Прежний брусок во всю ширину выходил сквозь стекло на 4,3 см и читался снаружи как парящий блок. `fitUnderGlass` остаётся страховкой: опускает всё, что ближе `GLASS_CLEARANCE` (2 см) к стеклу, — теперь это ножка зеркала и верх дверных накладок у стоек (≈440 вершин), полка не трогается. `npm run check:3d` собирает кокпит поверх стёкол обеих моделей и падает при зазоре меньше 2 см. На торпедо со стороны пассажира — табличка клуба (`DASH_LOGO`, меш `dash-logo`): сетка вдоль лобового стекла на 3 см под ним, лицом наружу, логотип шапки сайта на тёмном поле с тонкой рамкой — читается снаружи сквозь стекло. Картинку кладёт `interior.setLogo(image)` из `mount()` (та же, что для стены, повторно не грузится); до неё — тёмная табличка с той же программой шейдера.
- `drops.js` — капли «Антидождя» на лобовом стекле: одна геометрия на все капли (сплюснутые полусферы по 40 треугольников, 180 капель, на телефоне 80 — в 1,6 раза крупнее, иначе в узкой области 3D их не видно), место и наклон — по карте стекла (`glassMap`, верхняя поверхность), материал с настройками стекла фар — та же программа шейдера, при первом показе ничего не компилируется. Вершины пересчитываются только на кадрах эффекта; в остальное время меш скрыт.
- `models.js` — манифест моделей (адрес с хешем и размер); создаёт `npm run optimize-3d`.

Модели — `dist/assets/3d/porsche-930-{desktop,mobile}.<хеш>.glb`, собираются `npm run optimize-3d`
из `source/3d/porsche-930.glb` (исходник v1, в `dist` не публикуется). Отчёт с размерами
и sha256 — `source/3d/optimize-report.json`. `npm run check:3d` сверяет бандл, модели и манифест.

## API

```js
const {mount} = await import('./porsche3d.bundle.js');
const scene = await mount({
  container,            // элемент с position: relative/absolute; canvas добавится последним ребёнком
  signal,               // AbortSignal: отмена → промис отклоняется с AbortError, всё созданное освобождается
  quality: 'auto',      // 'high' | 'low' | 'auto' (телефон, сенсор без мыши, ≤2 ГБ, Save-Data → low)
  reducedMotion,        // по умолчанию из prefers-reduced-motion: ракурсы без перелёта, без инерции
  startView: 'overview',
  fadeIn: true,         // canvas проявляется после первого кадра
  interactive: true,    // поворот и приближение рукой
  stallTimeout: 15000,  // мс без новых байт → Porsche3DError('timeout')
  onProgress({loaded, total, ratio}),  // total — из манифеста (верно и при сжатии на хостинге)
  onPhase(name),        // 'download' → 'prepare' (скачано, готовим сцену)
  onFirstFrame(),       // первый кадр нарисован
  onError(error),       // после запуска: потеря контекста WebGL (сцена уже закрыта)
  onViewChange(name),   // ракурс | 'free' (повернули рукой)
  onInteract(kind),     // 'press' | 'pinch' | 'wheel' — человек взялся за машину
});
scene.showService(zoneId);    // id из dist/js/config.js ZONES → ракурс и эффект работы
scene.showBase();             // ничего не выбрано: общий вид, пыльная машина
scene.reset();                // «Общий вид»: исходная камера и приближение
scene.view('overview' | 'body' | 'wheel' | 'wing' | 'front' | 'hood' | 'reflection' | 'headlight' | 'sill' | 'windscreen');
scene.rotateBy(azDeg, polarDeg);  // клавиатура: поворот в градусах
scene.zoomBy(factor);         // <1 — ближе, >1 — дальше; пределы 0,72–1,3 от расстояния ракурса
scene.setSafeArea({top, right, bottom, left});  // свободная часть кадра, px (кнопки и подпись поверх)
scene.setSuspended(reason, on);  // пауза по причине страницы
scene.setReducedMotion(bool);
scene.stats();                // кадры, вызовы отрисовки, треугольники, память, timings этапов, effect (вид, доля, свет, капли)
scene.dispose();              // освобождает видеопамять и удаляет canvas; повторный вызов безопасен
```

Ошибки `mount()` — `Porsche3DError` с `code`: `webgl` (нет WebGL 2), `load` (сеть, HTTP),
`timeout`, `compile` (шейдеры), `context-lost`; отмена — `DOMException` `AbortError`. Во всех
случаях canvas уже удалён. Повторный `mount()` закрывает предыдущую сцену — двух сцен не бывает.
Скачанная модель остаётся в памяти модуля: после `dispose()` повторный `mount()` не ходит в сеть.

## Работы и эффекты

`SERVICE_VIEWS` (views.js) — ракурс для каждой работы гаража; `SERVICE_FX` — эффект работы,
только там, где модель показывает его убедительно. Эффект играет после того, как камера доехала;
выбор другой работы сразу останавливает прежний (свет гаснет, капли убираются), рука (поворот,
приближение) эффект не прерывает.

- `wash` — пыль с бортов смывается (`uClean` в шейдере лака): программы мойки.
- `gloss` — риски полировки (`uFinish`) исчезают и по борту идёт свет, камера медленно ведёт
  вдоль борта: полировка с керамикой.
- `glow` — мягкий блик ~2 с проходит по детали работы и гаснет: тот же свет `room.sweep` (новый
  источник пересобрал бы шейдеры и удорожил каждый пиксель), путь, сила и дальность — `GLOW` по
  ракурсу; дальность обрезает свет: соседние детали он почти не задевает, у колеса и крыла на полу — лишь мягкое пятно. Материалы машины
  не меняются. Диски — обод колеса; сколы — переднее крыло; оклейка зон риска — передняя кромка
  капота; полная оклейка — весь левый борт; фары (полировка, оклейка) — рефлектор и кольцо левой
  фары; керамика — капот. Химчистка и кожа блика не получают: свет внутри упрощённого салона из
  ракурса борта почти не виден, у них только ракурс.
- `rain` — «Антидождь передней полусферы»: капли садятся на лобовое стекло, стягиваются в
  бусины и скатываются, затем стекло чистое (~4 с, `drops.js`).

Без эффекта — только ракурс: бронирование и ремонт стекла (блик на стекле — точка в пару
пикселей, а свет за стеклом освещал бы торпедо), «Антидождь всех стёкол» (в профиль капли на
лобовом не видны, боковые стёкла почти отвесные — карты для них нет). Салон модели упрощён,
поэтому химчистка и кожа — общий вид борта (`body`), без пролёта внутрь; капли на капоте
(прежний `water.js`) убраны — в ракурсе гаража их не видно.

При «уменьшить движение» эффекты не анимируются: мойка и полировка сразу в итоге, блика нет,
капли стоят бусинами без движения. На телефоне (`quality: 'low'`) капель 80 вместо 180; блик
ничего не стоит — свет в сцене есть всегда. `npm run check:3d` проверяет: эффекты только
известного вида, у блика есть путь для ракурса работы, капли — только в ракурсе лобового стекла
и лежат на его внешней стороне на обеих моделях.

## Поведение

- Сцена живёт в модальном окне гаража, страница за ним неподвижна, поэтому жесты целиком
  принадлежат сцене: у canvas `touch-action: none`. Мышь и палец — поворот вокруг машины и наклон
  55°–86°, без сдвига; инерция 0.08 (без неё при «уменьшить движение»). Два пальца, колесо мыши
  и `zoomBy()` — приближение в пределах 0,72–1,3 от расстояния ракурса; смена ракурса его сбрасывает.
- Кадр рисуется только при изменении; неподвижная камера — ноль кадров. Эффект работы рисует
  кадры, пока идёт (до ~4 с), затем цикл снова стоит. Если камера уже в ракурсе работы (у
  фар, салона, общего вида по нескольку работ), перелёта нет — эффект начинается сразу. Вне экрана
  (IntersectionObserver), на скрытой вкладке и при `setSuspended` цикл стоит; после `dispose()`
  кадров нет вовсе.
- До готовности шейдеров кадр не рисуется, текстуры загружаются на видеокарту по одной,
  Meshopt распаковывается в фоновых потоках: интерфейс гаража отвечает и во время запуска.
  Синхронные проверки шейдеров выключены (включаются `?p3d-debug`).
- Пока камера движется, а кадры идут дольше ~30 мс, разрешение снижается до 70 %; остановилась —
  последний кадр снова в полном разрешении.
- Ракурсы вписываются в свободную часть контейнера (`setSafeArea`): гараж передаёт высоту
  кнопок сверху и подписи снизу, машина кадрируется между ними.
