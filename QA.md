## Версия 3.0: «Оживить Porsche» — 27 сентября 2026

Headless Chrome через CDP на реальной видеокарте (ANGLE, AMD Radeon Vega 8, D3D11), локальный
сервер `serve.cjs`. Замеры локальные, не Lighthouse и не живой хостинг.

**Размеры 3D (грузятся только после нажатия), байт:**

| Ресурс | raw | gzip | brotli |
|---|---|---|---|
| исходная модель v1 `source/3d/porsche-930.glb` (не публикуется) | 14 919 340 | — | — |
| `assets/3d/porsche-930-desktop.<хеш>.glb` | 2 228 272 | 1 708 437 | 1 691 013 |
| `assets/3d/porsche-930-mobile.<хеш>.glb` | 1 201 100 | 931 923 | 925 015 |
| `js/porsche3d.bundle.js` (three r180 + GLTFLoader + декодер Meshopt) | 612 835 | ~160 300 | ~143 800 |

Модель v1 для сравнения: оптимизированная 8 937 688 байт, бандл сцены 638 314. Треугольников
241 260 → 193 241 (компьютер) / 122 553 (телефон); мешей 75 → 10; окружение для отражений
генерируется на месте (0 байт). Сжатие: Meshopt (декодер ~20 КБ) вместо Draco (~300 КБ WASM),
WebP вместо KTX2/Basis (транскодер ~0,5 МБ). Точные числа — `npm run check:3d`.

**Обычный режим — без 3D-запросов.** Network с отключённым кэшем, 1440×900, до нажатия:
документ, 7 CSS (`style`, `cinematic`, `stage`, `proof`, `configurator`, `catalog`,
`porsche3d`), 4 шрифта WOFF2, логотип SVG, favicon, `gsap` и `ScrollTrigger`, модули
`main`, `config`, `ui`, `configurator`, `proof`, `live3d`, `stage`, кадры витрины
`cf-hero-dirty`, `cf-foam-crop`, `cf-interior-seat`, `cf-rq-bay`, `cf-bead-macro`,
`cf-hero-rear-wide` — 29 запросов, ни одного к `porsche3d.bundle.js`, `.glb`, three.
После нажатия — ровно два: `js/porsche3d.bundle.js` и модель (`…-desktop` или `…-mobile`).
Проверка WebGL для показа кнопки — `WebGL2RenderingContext` сразу и пробный контекст в простое
после `load`; движок при этом не грузится.

**Скорость обычного режима, v2.0 (site-v2) против v3.0, медиана трёх загрузок без кэша:**

v3 добавляет два файла обычного режима: `css/porsche3d.css` (10,8 КБ) и `js/live3d.js` (~21 КБ,
без сжатия). На замедленном профиле LCP на ~110 мс позже, самая длинная задача на ~40 мс длиннее
— в пределах разброса, но разница есть.

**Запуск 3D (после нажатия):** первый кадр локально через 0,5–1,0 с (модель из сети ~50 мс,
разбор 0,3 с, шейдеры и текстуры 0,3–0,7 с). Самая длинная задача главного потока при запуске
~80 мс (CPU ×1) и ~220 мс (CPU ×4): шейдеры собираются параллельно (KHR_parallel_shader_compile)
и до готовности кадр не рисуется, текстуры грузятся на видеокарту по одной, Meshopt распаковывается
в фоновых потоках. До этих правок первый рендер блокировал страницу на 1,4 с. Показ — ~65 кадров/с
на 960×600; в покое 0 кадров.

**Поведение (проверено запуском):**
- 1440×900, 1366×657, 390×844, 320×640, 844×390, 568×320 и `?motion=reduce` (1440, 390, 568, 844):
  во всех состояниях ряда (обычный, загрузка, 3D, после показа) нет наложений на hero, «Записаться»,
  SCROLL, «Гараж услуг», шапку; `scrollWidth = clientWidth`; ошибок в консоли нет. В статичном
  режиме на 568×320 ряд сначала ложился на подзаголовок — исправлено отступами в `porsche3d.css`.
- Медленная сеть (180 КБ/с): процент растёт («25%»), «Отмена» → обычный вид, «Загрузка отменена.»;
  повтор доходит до 3D. Отмена и новый запуск через 0–600 мс после старта — одна сцена, без ошибок.
- Модель заблокирована → «Не удалось загрузить 3D», фокус на «Повторить», фото на месте; после
  разблокировки «Повторить» → 3D. Модель не приходит 15 с → ошибка (15,2 с).
- Потеря контекста WebGL → «3D остановилось», canvas удалён, фото.
- Двойной клик по «Оживить Porsche» — одна загрузка, не отменяется.
- Колесо мыши над canvas листает страницу (0 → 300 px). Телефон 390×844: горизонтальный жест
  по машине поворачивает (ракурсы сбрасываются, страница не едет), вертикальный листает (285 px);
  `touch-action: pan-y`.
- Уход к главам: `#scene[data-p3d-away]`, canvas `opacity 0`, отрисовка стоит; наверх — 3D снова.
- «Обычный вид» при `scrollY = 12` — прокрутка та же, canvas удалён, фокус на «Оживить Porsche»;
  повторное включение без запросов в сеть, сразу «Общий вид» без показа. Esc в ряду — обычный вид.
- Запись: нижняя кнопка и «Записаться» гаража открывают окно в 3D-режиме.
- Гараж (1440 и 390): «Показать в 3D» → загрузка (aria-busy) → камера к детали; диски — колесо;
  сколы (пара «до/после») — крыло, `has-pair` снят; химчистка салона — фото; «Показ» гаража
  выключает переключатель (`aria-disabled`), после — снова доступен; закрытие гаража — фото,
  видеопамять освобождена. Открытие гаража при 3D на первом экране — переключатель уже нажат.
- Копия `dist` после `stamp-assets` и `prune-deploy`: `import('./porsche3d.bundle.js?v=…')`,
  модель по имени с хешем, 3D запускается; ссылки на лицензии в `credits.html` отдают 200.

**Не проверено:** реальный телефон, iOS Safari, слабые GPU и первый запуск с пустым кэшем
шейдеров, живой GitHub Pages (сжимает ли он .glb). В headless экран маленький, поэтому
`quality: 'auto'` выбирал облегчённую модель и на 1440×900; на обычном компьютере с экраном
от 700 px по короткой стороне должна грузиться `…-desktop` — проверить вручную во вкладке Network.

## Автоматические проверки

`npm run check`: синтаксис ES modules; пути JS/CSS/изображений/шрифтов; локальные якоря; 6 точек прокрутки; 4 услуги; цены из предоставленного JSON, в том числе цены «от» в «Гараже услуг»; кадры витрины в двух размерах; 3D только через `import()` по нажатию; ссылки онлайн-записи обеих площадок. Затем `check:3d`: бандл собран из `src/porsche3d`, модели совпадают с `source/3d/optimize-report.json` и манифестом, имена с хешем, бюджеты размеров, Meshopt и WebP, ракурс или фото у каждой работы гаража.
