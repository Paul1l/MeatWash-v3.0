# Meat Wash — правила проекта

Статический сайт сети детейлинг-студий Meat Wash (Мясницкая, Технопарк), три страницы:
главная (`index.html`: первый экран — статичная фотография и вход в «Гараж услуг», превью услуг,
промоблок гаража, «До и после», клуб коротко, локации, «Больше, чем сервис»; «Гараж услуг» — одно
окно с 3D-моделью, которая грузится только по нажатию «Открыть 3D-гараж»), `services.html` (каталог цен, запись) и `about.html`
(о клубе, фото, «Перед визитом», локации). Запись — во внешний yclients, карта — окно
с виджетом Яндекс Карт.
За основу взята версия https://meat-wash.vercel.app (действующий сайт клиента, его не трогаем),
поверх неё — наши исправления записи, доступности, мета и деплоя.
Эти правила дополняют глобальную web-команду (`~/.claude/agents/`) и важнее общих, где конкретнее.

## Устройство

- `dist/` — это и есть сайт: `index.html`, `services.html`, `about.html`, `credits.html`, `css/`,
  `js/`, `assets/`. Что генерируется (руками не править — править источник и перегенерировать):
  - общие части страниц — шапка с меню, подвал, окна записи и карты, `.mobile-cta`, карточки
    локаций, блок записи `#book`, клубный блок `#membership` (главная и «О нас») — живут в `src/partials/*.html` и вставляются между маркерами
    `<!-- SHARED:<имя>:START/END -->` скриптом `npm run pages` (`scripts/pages.mjs`; там же список,
    какая часть на какой странице, и подстановки `{{home}}`, `{{current:…}}`, `{{loc:<id>:<поле>}}`);
  - каталог на `services.html` (`CATALOG`), превью четырёх направлений на главной (`PREVIEW`)
    и `dist/js/data.js` (цены и филиалы для скриптов) — `npm run catalog` из JSON;
  - `npm run build` = catalog + pages. Результат коммитится; CI ничего не генерирует —
    `npm run check` падает, если страница разошлась с источником.
  Исходники со сборкой есть ещё у 3D-гаража: `src/porsche3d/` → `dist/js/porsche3d.bundle.js`,
  `source/3d/` → `dist/assets/3d/`.
- Входы скриптов: главная — `main.js` (шапка после первого экрана, кнопки `[data-garage-open]`,
  `./#garage`, шторки); внутренние — `page.js`
  (только общее: `ui.js`, `catalog.js`, шторки `proof.js` — если на странице есть `[data-ba]`).
  `ui.js` — общее всех страниц: меню, окна записи/услуги/карты, якоря (прямой заход на
  `services.html#price-*` раскрывает `details`), блокировка прокрутки (`html.is-locked`,
  `body.dialog-open`). `maps.js` — окно карты, грузится в простое после `load`; до этого «На карте» —
  обычная ссылка на карточку Яндекса. `body.js` — выбранный тип кузова (sessionStorage `mw:body`),
  общий для каталога и гаража. Стили всех страниц: `style.css` → `cinematic.css` → … → `pages.css`
  (страницы, превью, окно карты, действия локаций); на главной ещё `garage.css`.
- `dist/js/garage.js` — «Гараж услуг»: строит `<dialog id="garage">`, состояния `data-state`
  (`loading` → `ready` | `error` | `nogl`), проба WebGL 2 по нажатию (sessionStorage `mw:webgl2`),
  `import('./porsche3d.bundle.js')`, отмена загрузки при закрытии, выбор работ (sessionStorage
  `mw:garage`), итог, запись. `config.js` — работы гаража (`ZONES` с `price: {program}|{item}` —
  ссылка на позицию каталога, название подставляется из неё), категории, `EXCLUSIVE`, `includedIn`,
  `garageSum`, наборы; `proof.js` — шторки блока «До и после» (`#proof`).
  Кнопки входа — `[data-garage-open]` «Открыть 3D-гараж»: на первом экране (`.garage-entry`) и
  в промоблоке (`#garage-promo`); тизер `services.html` ведёт на `./#garage`.
- Кадры: `dist/assets/shots/cf-<id>.webp` (1600 px) и `cf-<id>-s.webp` (900 px) — первый экран
  (`cf-hero-clean`), превью гаража (`cf-hero-dirty`), «До и после», превью услуг. Кадры прежней
  фото-витрины в репозитории остались, `prune-deploy` не пускает в выкладку те, на которые нет ссылок.
- `dist/assets/meatwash-content.json` — единый источник цен, услуг, адресов, часов, ссылок записи
  и карт (org id, координаты `lat`/`lon` и `mapWidget` — из данных виджета Яндекса, 28.09.2026).
  Адреса и часы в нём — в том виде, в каком их показывает сайт; из JSON собираются карточки
  локаций, подвал, окна записи и карты, каталог, превью и `js/data.js` (гараж — цены и состав
  программ мойки, карта).
- Стили: `style.css` (токены, база, первый экран) → `cinematic.css` (сплошная шапка, первый
  экран на телефоне и в альбоме, нижняя кнопка записи, «уменьшить движение») → `proof.css` →
  `catalog.css` → `pages.css` → `garage.css` (вход, промоблок, окно гаража). Многие правила
  `style.css` перекрыты в `cinematic.css` — проверяй, где правило действует на самом деле.
- 3D грузится **только по нажатию** «Открыть 3D-гараж»: `garage.js` делает
  `import('./porsche3d.bundle.js')`, бандл (three r180, GLTFLoader, декодер Meshopt — внутри,
  importmap не нужен) сам скачивает модель. До нажатия ни движок, ни модель, ни декодеры не
  запрашиваются. `npm run check` падает на статическом импорте бандла, `<script>`, preload/prefetch,
  ссылке на `.glb`, `assets/3d` или importmap в коде страницы; разрешён только `import()` строкой.
- Исходник модуля — `src/porsche3d/` (`index.js` — mount, камера, поворот и приближение,
  `views.js` — ракурсы и работы гаража (`SERVICE_VIEWS`, `SERVICE_FX`), `room.js` — помещение
  и свет, `interior.js` — кокпит, `models.js` — манифест моделей, создаётся скриптом).
  После правки: `npm run bundle-3d` и закоммитить бандл.
- Модели: `source/3d/porsche-930.glb` (исходник, в `dist` не публикуется) → `npm run optimize-3d`
  → `dist/assets/3d/porsche-930-{desktop,mobile}.<хеш>.glb` + `src/porsche3d/models.js` +
  `source/3d/optimize-report.json`, затем `npm run bundle-3d`. Имя с хешем содержимого —
  смена модели не ловит старый кэш. Руками GLB и `models.js` не править.
- `scripts/prune-deploy.mjs` при публикации убирает из копии `dist` то, что страница
  не запрашивает (ttf, логобук в PNG и других цветах, картинки прошлых версий макета,
  кадры `assets/shots` без ссылок).

## Ловушки

- Первый экран — статичная фотография: закреплённой сцены, глав, ScrollTrigger и GSAP больше нет
  (check падает на их остатках в `index.html`, `style.css`, `cinematic.css`). Главная кнопка на
  первом экране — «Записаться» (на телефоне в портрете — `.mobile-cta` внизу), рядом вход в гараж
  светлой кнопкой `.btn--light`. На телефоне в портрете hero — колонкой, фото занимает остаток
  высоты (`flex: 1 0 190px`, `max-height: 62svh`).
- `./#garage` (тизер на services.html) открывает гараж на главной сразу; хеш убирается.
- Гараж — native `<dialog>`: Esc перехватывается (`cancel`) и идёт через `close()` — отмена загрузки
  (`AbortSignal`), `dispose()` сцены, снятие блокировки, прокрутка на прежнее место, фокус на
  открывшую кнопку. Порядок в `close()`: сначала `dialog.close()`, потом фокус — иначе браузер
  возвращает фокус на элемент до `showModal` (после `./#garage` — body). Щелчки первые 400 мс и
  второй щелчок двойного по кнопке входа окно не закрывают.
- Поздно закончившаяся загрузка сверяет свою задачу (`job !== mine`) и закрывает сцену сама —
  окно не открывает. Повторный `mount()` закрывает предыдущую сцену: две сцены невозможны.
- Процент — только для модели (размер из манифеста `models.js`, поток отдаёт распакованные
  байты); бандл и подготовка сцены — индикатор без процента. Панель услуг видна только в `ready`,
  фон области 3D — тёмная студия: фото не выдаём за работающий 3D.
- В окне гаража страница неподвижна, поэтому у canvas `touch-action: none`: палец крутит машину по
  обеим осям, два пальца, колесо и «+»/«−» — приближение (0,72–1,3). Список листается внутри
  `.garage__list` (`overscroll-behavior: contain`), вкладки — вбок.
- Кнопки сверху и подпись работы снизу лежат поверх области 3D: `garage.js` передаёт их высоту в
  `setSafeArea`, машина кадрируется между ними.
- Работы → ракурсы и эффекты (`src/porsche3d/views.js`): эффекты материалов — только `wash`
  (пыль смывается) и `gloss` (риски и свет по борту); салон модели упрощён — химчистка и кожа
  показываются общим видом борта, без пролёта внутрь; капли керамики убраны. check:3d проверяет,
  что у каждой работы есть ракурс, а эффекты только эти.
- «Записаться» в гараже: `close()`, затем общий обработчик `ui.js` (`data-book`) открывает выбор
  филиала с «Вы выбрали: …» — окна не накладываются. В yclients состав не передаётся.
- `prefers-reduced-motion` и `?motion=reduce`: камера переходит к ракурсам мгновенно, без инерции
  и проезда вдоль борта; гараж при этом работает.
- Модель выбирается по устройству (`pickQuality`): облегчённая — сенсор без мыши, память < 4 ГБ
  (Chrome округляет вниз) или Save-Data; узкое окно с мышью получает модель для компьютера.
- Каталог (`services.html`, маркеры CATALOG), превью (`index.html`, PREVIEW) и `js/data.js` генерирует
  `scripts/catalog.mjs` из JSON; общие части страниц — `scripts/pages.mjs` из `src/partials`.
  Правь шаблон, фрагмент или данные, затем `npm run build`. Ссылки внутри фрагментов — через
  подстановки (`{{home}}#locations` → `#locations` на главной и `./#locations` на остальных).
- Гараж: цены работ — ссылки на каталог (`price: {program: i}` или `{item: "название"}`), название
  работы — то же, что в каталоге; программы мойки взаимоисключающие (`EXCLUSIVE`: каждая
  следующая включает предыдущую); работа из состава выбранной программы (`programIncludes` в JSON,
  например «Чернение шин» в «Детейлинг-мойке от реагентов») отмечается «входит в программу» и
  в сумму не попадает (`includedIn`, `garageSum`); цена мойки — для выбранного кузова (`body.js`,
  общий выбор с каталогом). Check сверяет название и цену каждой работы, сумму каждого набора по
  всем четырём кузовам и отсутствие повторного начисления.
- Окно карты: iframe виджета (`map-widget/v1/org/<slug>/<id>/?ll=…&z=16` — формат кода
  «Поделиться → Встроить» карточки организации) создаёт `maps.js` только при открытии и только
  для выбранной студии, при закрытии удаляет. В разметке iframe и адреса виджета быть не должно
  (check). Поверх углов iframe ничего не класть: там элементы управления и атрибуция Яндекса.
- Push в `main` сразу публикует сайт на GitHub Pages (`pages.yml`), его видит клиент.
  В `main` не пушить — только ветка и pull request; сливает владелец.
- Форм сбора данных нет намеренно. Запись — ссылками в yclients, у каждого филиала своя:
  Мясницкая `n975571…/company/906067`, Технопарк `n1982508…/company/1743348`
  (общая `n975571.yclients.com` открывает только Мясницкую — на странице её быть не должно,
  это проверяет `npm run check`). Окно записи игнорирует клики первые 400 мс и второй клик
  двойного: иначе двойной клик закрывал окно или сам открывал Мясницкую.
  Предвыбор услуги в yclients (`?o=s<ID услуги>`) форма поддерживает (проверено 28.09.2026), но
  не используется: параметр недокументированный, «Трёхфазной» на Мясницкой нет, а цены программ
  на Мясницкой в yclients выше, чем в JSON. Решает владелец.
- Цены и факты — только из JSON (цены «от» в гараже тоже проверяются). Не выдумывать цифры,
  отзывы, клиентов, акции, программы лояльности.
- `canonical`, `og:url`, `og:image`, JSON-LD, `robots.txt`, `sitemap.xml` указывают на
  GitHub Pages (`paul1l.github.io/MeatWash-v3.0`). Если сайт переедет на другой адрес — менять все.
- На Windows `core.autocrlf=true`; `.gitattributes` держит текстовые файлы в LF.
- `stamp-assets.mjs` при публикации ставит `?v=` только к CSS, JS и относительным import (в том
  числе к `import('./porsche3d.bundle.js')`). Пишет всегда в `dist` репозитория — локально запускать
  только на копии репозитория. Кадры `assets/shots` адресуются без версии; фото первого экрана —
  обычный `<img>` с `fetchpriority="high"`.

## Внешний вид

Вид — как в версии Vercel: бордово-бежевые токены в начале `style.css`, горизонтальный логотип
в шапке, заголовки Arsenal SC, текст Arsenal (обе — шрифты брендбука; начертания 400 и 700,
промежуточных нет). Логобук «Стенки Бюро» (`dist/assets/brand/`, фирменный `#861A22`) — справка,
а не требование. Sloop Script не подключён (платный).

## Проверки

```
npm run check          # ресурсы (src, srcset, CSS url), ссылки, якоря, цены и названия гаража,
                       # первый экран без сцены, 3D только через import() по нажатию,
                       # ссылки записи обоих филиалов; затем check:3d — бандл свежий,
                       # модели совпадают с отчётом, бюджеты, ракурсы работ
npm run optimize-3d    # после замены source/3d/porsche-930.glb или настроек сжатия
npm run bundle-3d      # после правки src/porsche3d
npm run build          # = catalog (каталог, превью, js/data.js из JSON) + pages (src/partials)
npm run catalog        # после правки JSON или шаблона каталога
npm run pages          # после правки src/partials
npm start              # http://127.0.0.1:4173, открывать через file:// нельзя
```

Вёрстку проверять на всех трёх страницах: 320, 390, 430, 768, 1024, 1440, ноутбучной высоте (1366×657, 1280×720) и телефоне
в альбомной ориентации: без горизонтальной прокрутки (мерить `scrollWidth`), без наложений,
без ошибок в консоли; отдельно — `?motion=reduce`. Гараж — во всех состояниях (загрузка с медленной
сетью, готов, ошибка, нет WebGL), закрытие во время загрузки, повторные открытия (один canvas),
на телефоне — жесты и «Свернуть услуги»; закрытие, итог и «Записаться» в пределах экрана.
WebGL в headless Chromium без видеокарты — `--use-angle=swiftshader --enable-unsafe-swiftshader`
(медленно: кадр ~20 с), с видеокартой — CDP.
