# Meat Wash — правила проекта

Статический сайт сети детейлинг-студий Meat Wash (Мясницкая, Технопарк). Основные страницы:
главная (`index.html`: первый экран — статичная фотография и вход в «Гараж услуг», превью услуг,
промоблок гаража, «До и после», клуб коротко, локации, «Больше, чем сервис»; «Гараж услуг» — одно
окно с 3D-моделью, которая грузится только по нажатию «Открыть 3D-гараж»), `services.html` (четыре категории услуг — Мойка, Детейлинг, Защита, Помощь — переключателями, видна одна; оклейка и ремонт стёкол — выделенными подразделами; мойка — запись в YCLIENTS, остальное — заявка с фото) и `about.html`
(о клубе, фото, «Перед визитом», локации); ещё раздел «Статьи» (`articles.html` и статьи
`article-*.html`), Политика обработки персональных данных (`privacy.html`) и Согласие
(`consent.html`). Запись — во внешний yclients, карты — виджеты Яндекс Карт прямо в карточках филиалов;
Яндекс Метрика — только с согласия посетителя (уведомление о cookie).
За основу взята версия https://meat-wash.vercel.app (действующий сайт клиента, его не трогаем),
поверх неё — наши исправления записи, доступности, мета и деплоя.
Эти правила дополняют глобальную web-команду (`~/.claude/agents/`) и важнее общих, где конкретнее.

## Устройство

- `dist/` — это и есть сайт: `index.html`, `services.html`, `about.html`, `articles.html`,
  `article-*.html`, `privacy.html`, `consent.html`, `sitemap.xml`, `css/`, `js/`, `assets/`. Что генерируется (руками не править — править источник и перегенерировать):
  - общие части страниц — шапка с меню, подвал, окна записи и заявки, `.mobile-cta`, карточки
    локаций с картами, блок записи `#book`, клубный блок `#membership` (главная и «О нас»), блок `analytics`
    в `<head>` (мета-теги Вебмастера и номера счётчика) — живут в `src/partials/*.html` и вставляются между маркерами
    `<!-- SHARED:<имя>:START/END -->` скриптом `npm run pages` (`scripts/pages.mjs`; там же список,
    какая часть на какой странице, и подстановки `{{home}}`, `{{locations}}` — `''` на страницах с блоком локаций, `./` на остальных,
    `{{current:…}}`, `{{loc:<id>:<поле>}}`);
  - каталог на `services.html` (`CATALOG`: переключатели и панели четырёх категорий с подразделами),
    превью на главной (`PREVIEW`: четыре карточки — по одной на категорию)
    и `dist/js/data.js` (цены и филиалы для скриптов) — `npm run catalog` из JSON;
  - статьи, список статей, Политика, Согласие и `sitemap.xml` — `npm run content`
    (`scripts/content.mjs`) из `src/content/` (список страниц и мета — `src/content/pages.mjs`,
    тела — HTML с подстановками `{{price:<работа каталога>}}`, `{{program-from:i}}`,
    `{{program-includes:i}}`, `{{op:<реквизит>}}`, `{{site:url|date}}`, `{{home}}`, `{{loc:…}}`);
  - `npm run build` = catalog + content + pages. Результат коммитится; CI ничего не генерирует —
    `npm run check` падает, если страница разошлась с источником.
  Исходники со сборкой есть ещё у 3D-гаража: `src/porsche3d/` → `dist/js/porsche3d.bundle.js`,
  `source/3d/` → `dist/assets/3d/`.
- Входы скриптов: главная — `main.js` (шапка после первого экрана, кнопки `[data-garage-open]`,
  `./#garage`, шторки); внутренние — `page.js`
  (только общее: `ui.js`, `catalog.js`, шторки `proof.js` — если на странице есть `[data-ba]`).
  `ui.js` — общее всех страниц: меню, окна записи и заявки, ленивая загрузка карт, уведомление о cookie и цели
  Метрики (`analytics.js`), якоря (раскрывает `details` цели), блокировка прокрутки (`html.is-locked`,
  `body.dialog-open`). `catalog.js` — каталог `services.html`: из ссылок `nav.catalog__tabs` делает
  вкладки (WAI-ARIA; без скриптов все четыре панели идут подряд), по хешу — заход по адресу,
  `hashchange`, клик по ссылке на тот же якорь — открывает панель с целью (прежние `#price-film`,
  `#price-glass`, `#program-2` и др. ведут в свой подраздел), выбор кузова и метка «на месте» у
  работ мойки. `maps.js` — карты филиалов в карточках «Локации» (`.location__map[data-map-embed]`):
  `ui.js` грузит его через `import()`, когда область карты подходит к экрану (запас 600 px), и он
  создаёт iframe этой студии; карты грузятся по очереди (следующая — после load предыдущей или
  через 8 с: на мобильной сети две сразу подолгу стояли недогруженными); iframe прозрачный, пока
  не загрузился (видна заглушка «Загружаем карту…», а не полусобранный виджет), через 12 с без
  load — виден как есть с плашкой-ссылкой; состояния `loading` → `loaded` | `error` (HEAD no-cors,
  «Повторить»), на сенсоре — слой-кнопка поверх карты, чтобы свайп листал страницу. `body.js` — выбранный тип кузова (sessionStorage `mw:body`),
  общий для каталога и гаража. Стили всех страниц: `style.css` → `cinematic.css` → … → `pages.css`
  (страницы, превью, карты локаций); на главной ещё `garage.css`.
- `dist/js/garage.js` — «Гараж услуг»: строит `<dialog id="garage">`, состояния `data-state`
  (`loading` → `ready` | `error` | `nogl`), проба WebGL 2 по нажатию (sessionStorage `mw:webgl2`),
  `import('./porsche3d.bundle.js')`, отмена загрузки при закрытии, выбор работ (sessionStorage
  `mw:garage`), итог: мойка — «Записаться на мойку» (YCLIENTS), остальное — «Заявка с фото».
  `config.js` — работы гаража (`ZONES` с `price: {program}|{item}` — ссылка на позицию каталога,
  название подставляется из неё; цена `null` — после оценки; пояснение — из каталога), вкладки = четыре категории JSON,
  `EXCLUSIVE`, `includedIn` (по `programItems`), `garageSum`, `garageOpen`, `isWash`; готовых
  «наборов» нет — пакеты мойки («Экстерьер», «Премиум») — позиции каталога во вкладке «Мойка».
  `request.js` — окно «Заявка с фото» (`#request` в `dialogs.html`), грузится по первому
  `[data-request]`; `yclients.js` + `assets/yclients.json` (PR #5) — ссылка филиала с корзиной
  мойки; `proof.js` — шторки блока «До и после» (`#proof`).
  Кнопки входа — `[data-garage-open]` «Открыть 3D-гараж»: на первом экране (`.garage-entry`) и
  в промоблоке (`#garage-promo`); тизер `services.html` ведёт на `./#garage`.
- Кадры: `dist/assets/shots/cf-<id>.webp` (1600 px) и `cf-<id>-s.webp` (900 px) — первый экран
  (`cf-hero-clean`), превью гаража (`cf-hero-dirty`), «До и после», превью услуг. Кадры прежней
  фото-витрины в репозитории остались, `prune-deploy` не пускает в выкладку те, на которые нет ссылок.
- `dist/js/analytics.js` — Яндекс Метрика только после «Принять» в уведомлении о cookie (решение —
  localStorage `mw:consent`); номер счётчика — из `<meta name="mw-metrika">`; нет номера — нет ни
  уведомления, ни Метрики, `goal()` молчит. Цели: `booking_open`, `booking_branch`, `phone_click`,
  `map_open` (`source`: `footer` — «На карте» в подвале, `touch` — карту включили касанием,
  `map` — фокус ушёл в карту на компьютере), `garage_open`, `garage_ready`, `garage_book`, `garage_request`, `club_card`, `request_open`, `request_sent`. «Настройки cookie» в подвале открывают
  уведомление снова; отказ после согласия удаляет cookie `_ym*` и перезагружает страницу.
- `dist/assets/meatwash-content.json` — единый источник цен, услуг, адресов, часов, ссылок записи
  и карт (org id, координаты `lat`/`lon` и `mapWidget` — из данных виджета Яндекса, 28.09.2026).
  Адреса и часы в нём — в том виде, в каком их показывает сайт; из JSON собираются карточки
  локаций с картами, подвал, окна записи, каталог, превью и `js/data.js` (гараж — цены, состав
  программ, категории, карта, настройка заявок). `groups` — четыре категории в порядке показа: Мойка,
  Детейлинг, Защита, Помощь (`booking`: `yclients` у мойки, `request` у остальных; `desc` — подпись;
  `sections` — подразделы с `id` якоря, `items` — названия, `programs: true` — место программ мойки,
  `accent: true` — выделенный подраздел: оклейка и ремонт стёкол; позиции `[название, цена|null,
  короткое пояснение]`, null — «После оценки»); каждая позиция — ровно в одной категории и одном
  подразделе (check сверяет со списком перенесённых позиций); `programItems` — состав программ
  позициями каталога. Распределение и пояснения — предложение, ждут подтверждения владельца. Блок `site`: `analytics.metrika` (номер счётчика, цифры),
  `analytics.webmaster` (код Вебмастера: мета-тег `yandex-verification` и файл
  `dist/yandex_<код>.html` — его пишет `npm run content`, check сверяет), `operator` (реквизиты оператора
  ПДн для Политики и Согласий), `documentsDate` (дата редакции документов), `requests.endpoint`
  (адрес приёма заявок, null — не подключено). Пусто — Метрика и
  мета-тег не ставятся, в документах на месте реквизитов жёлтые пометки, check предупреждает.
- Стили: `style.css` (токены, база, первый экран) → `cinematic.css` (сплошная шапка, первый
  экран на телефоне и в альбоме, нижняя кнопка записи, «уменьшить движение») → `proof.css` →
  `catalog.css` → `pages.css` → `garage.css` (вход, промоблок, окно гаража). Многие правила
  `style.css` перекрыты в `cinematic.css` — проверяй, где правило действует на самом деле.
- 3D грузится **только по нажатию** «Открыть 3D-гараж»: `garage.js` делает
  `import('./porsche3d.bundle.js')`, бандл (three r180, GLTFLoader, декодер Meshopt — внутри,
  importmap не нужен) сам скачивает модель. До нажатия ни движок, ни модель, ни декодеры не
  запрашиваются. `npm run check` падает на статическом импорте бандла, `<script>`, preload/prefetch,
  ссылке на `.glb`, `assets/3d` или importmap в коде страницы; разрешён только `import()` строкой.
- Исходник модуля — `src/porsche3d/` (`index.js` — mount, камера, поворот и приближение,
  `views.js` — ракурсы и работы гаража (`SERVICE_VIEWS`, `SERVICE_FX`), `room.js` — помещение
  и свет, `interior.js` — кокпит, `models.js` — манифест моделей, создаётся скриптом).
  После правки: `npm run bundle-3d` и закоммитить бандл.
- Модели: `source/3d/porsche-930.glb` (исходник, в `dist` не публикуется) → `npm run optimize-3d`
  → `dist/assets/3d/porsche-930-{desktop,mobile}.<хеш>.glb` + `src/porsche3d/models.js` +
  `source/3d/optimize-report.json`, затем `npm run bundle-3d`. Имя с хешем содержимого —
  смена модели не ловит старый кэш. Руками GLB и `models.js` не править.
- `scripts/prune-deploy.mjs` при публикации убирает из копии `dist` то, что страница
  не запрашивает (ttf, логобук в PNG и других цветах, картинки прошлых версий макета,
  кадры `assets/shots` без ссылок).

## Ловушки

- Первый экран — статичная фотография: закреплённой сцены, глав, ScrollTrigger и GSAP больше нет
  (check падает на их остатках в `index.html`, `style.css`, `cinematic.css`). Главная кнопка на
  первом экране — «Записаться» (на телефоне в портрете — `.mobile-cta` внизу), рядом вход в гараж
  светлой компактной кнопкой `.btn--light.garage-cta` (44 px, по ширине текста; раз в 4,2 с — блик,
  поворот кубика и кольцо `box-shadow`; outline не трогать — он занят видимым фокусом). На телефоне в портрете hero — колонкой, фото занимает остаток
  высоты (`flex: 1 0 190px`, `max-height: 62svh`).
- `./#garage` (тизер на services.html) открывает гараж на главной сразу; хеш убирается.
- Гараж — native `<dialog>`: Esc перехватывается (`cancel`) и идёт через `close()` — отмена загрузки
  (`AbortSignal`), `dispose()` сцены, снятие блокировки, прокрутка на прежнее место, фокус на
  открывшую кнопку. Порядок в `close()`: сначала `dialog.close()`, потом фокус — иначе браузер
  возвращает фокус на элемент до `showModal` (после `./#garage` — body). Щелчки первые 400 мс и
  второй щелчок двойного по кнопке входа окно не закрывают.
- Поздно закончившаяся загрузка сверяет свою задачу (`job !== mine`) и закрывает сцену сама —
  окно не открывает. Повторный `mount()` закрывает предыдущую сцену: две сцены невозможны.
- Процент — только для модели (размер из манифеста `models.js`, поток отдаёт распакованные
  байты); бандл и подготовка сцены — индикатор без процента. Панель услуг видна только в `ready`,
  фон области 3D — тёмная студия: фото не выдаём за работающий 3D.
- В окне гаража страница неподвижна, поэтому у canvas `touch-action: none`: палец крутит машину по
  обеим осям, два пальца, колесо и «+»/«−» — приближение (0,72–1,3). Список листается внутри
  `.garage__list` (`overscroll-behavior: contain`).
- Панель гаража — без перегруза: четыре вкладки категорий (в одну строку, на панели уже 290 px —
  сетка 2×2), строка работы — название и цена, состав программы или пакета — по кнопке «Состав»
  (открыт один), внизу «Выбрано: N» с итогом — список выбранного (с «Убрать», раздельно мойка и
  заявка) раскрывается по нажатию, на телефоне занимает место списка. «Свернуть услуги» — в шапке
  окна, только на телефоне в портрете. Итог: «от N ₽», работы без цены — «+ после оценки: …».
- Кнопки сверху и подпись работы снизу лежат поверх области 3D: `garage.js` передаёт их высоту в
  `setSafeArea`, машина кадрируется между ними.
- Кокпит (`interior.js`): полка торпедо строится по карте стекла модели (`glassMap` → `glassV1`)
  с зазором 4,5 см и кромкой по кривой основания стекла, козырёк приборов, зеркало, козырьки;
  `fitUnderGlass` — страховка с зазором 2 см (ножка зеркала к стеклу, верх дверных накладок у
  стоек); check:3d проверяет зазор на обеих моделях. Текстуры кокпита — canvas без градиентов
  (в Node холст — заглушка). Логотип на стене гаража (`room.js`, `LOGO`) — файл шапки сайта, грузится
  только в mount(); стоит на 1 см ближе середин граней стены (стена — многогранник). Тот же
  логотип — на табличке на торпедо со стороны пассажира (`interior.js`, `DASH_LOGO`, меш
  `dash-logo`): сетка вдоль лобового стекла на 3 см под ним, лицом наружу — читается сквозь
  стекло; текстура с самого начала (тёмная заглушка), картинку кладёт `setLogo` — без
  компиляции при показе. check:3d: табличка есть на обеих моделях, целиком под стеклом, лицом наружу.
- Работы → ракурсы и эффекты (`src/porsche3d/views.js`, `SERVICE_FX`): `wash` (пыль смывается),
  `gloss` (риски и свет по борту), `glow` — мягкий блик по детали работы после перелёта камеры
  (колесо, крыло, капот, фара, борт): только существующий `room.sweep`, путь,
  сила и дальность — `GLOW[ракурс]`, новых источников света и правок материалов машины нет; `rain` —
  капли на лобовом стекле для «Антидождя передней полусферы» (`drops.js`: один меш, 180 капель на
  компьютере и 80 крупнее при quality low, позиции по верхней поверхности стекла из `glassMap`, та же
  программа шейдера, что у стекла фар, — без компиляции при показе; садятся, стягиваются в бусины
  и скатываются, ~4,4 с). Смена работы гасит прежний эффект, `dispose()` освобождает капли. Стекло
  (бронирование, ремонт) и «Антидождь всех стёкол» — только ракурс: блик на стекле не виден,
  у боковых стёкол нет карты высоты. Салон модели упрощён — химчистка и кожа показываются общим
  видом борта, без пролёта и без блика (свет в салоне почти не виден). check:3d проверяет ракурс каждой работы, вид эффекта,
  путь блика и положение капель на стекле на обеих моделях.
- Запись и заявка разделены везде (каталог, карточки, гараж, итог): мойка (категория `booking:
  yclients`) — окно филиалов, ссылка с корзиной мойки (`short?o=m-1s<id>…`, `yclients.js`);
  остальные работы (`booking: request`) — «Заявка с фото». Смешанный выбор в гараже: две кнопки,
  в YCLIENTS уходит только мойка, окно записи напоминает об остальных работах, окно заявки — о
  мойке; выбор остаётся в `mw:garage`. «Записаться» / «Заявка» в гараже: `close()`, затем общий
  обработчик `ui.js` (`data-book` / `data-request`) — окна не накладываются. Каждое открытие окна
  записи начинает со ссылок из разметки (иначе общая «Записаться» уносила прошлую корзину).
- `prefers-reduced-motion` и `?motion=reduce`: камера переходит к ракурсам мгновенно, без инерции
  и проезда вдоль борта, блика нет, капли стоят бусинами без движения; гараж при этом работает.
- Модель выбирается по устройству (`pickQuality`): облегчённая — сенсор без мыши, память < 4 ГБ
  (Chrome округляет вниз) или Save-Data; узкое окно с мышью получает модель для компьютера.
- Каталог (`services.html`, маркеры CATALOG), превью (`index.html`, PREVIEW) и `js/data.js` генерирует
  `scripts/catalog.mjs` из JSON; общие части страниц — `scripts/pages.mjs` из `src/partials`.
  Правь шаблон, фрагмент или данные, затем `npm run build`. Ссылки внутри фрагментов — через
  подстановки (`{{home}}#locations` → `#locations` на главной и `./#locations` на остальных).
- Гараж: цены работ — ссылки на каталог (`price: {program: i}` или `{item: "название"}`), название
  работы — то же, что в каталоге; программы и пакеты мойки взаимоисключающие (`EXCLUSIVE`: каждая
  следующая включает предыдущую), а также «Полировка + 2 слоя керамики» / «Керамическое покрытие»,
  зоны риска / полная оклейка, антидождь передний / всех стёкол. Работа из состава выбранной
  программы или пакета (`programItems` в JSON — позиции каталога, с составом предыдущих) отмечается
  «входит в пакет» и в сумму не попадает (`includedIn`, `garageSum`); цены «после оценки» в сумму
  не входят, итог называет их отдельно. Чернения шин как отдельной работы нет (оно в составе
  «Детейлинг-мойки от реагентов»), химчистка — «Детейлинг-химчистка салона» целиком. Цена мойки —
  для выбранного кузова (`body.js`, общий выбор с каталогом). Check сверяет название, цену и
  категорию каждой работы, пакеты с составом по всем кузовам и отсутствие повторного начисления.
- Метрика — только через `analytics.js` после согласия: кода счётчика (`mc.yandex.ru`,
  `tag.js`) и noscript-пикселя в разметке быть не должно (check). Счётчик 113253931, параметры `init` —
  как в его коде из интерфейса Метрики, Вебвизор включён: он назван в уведомлении, Политике и
  Согласии, check сверяет `webvisor` с текстами — выключая, правь и их. Номер счётчика и код
  Вебмастера — только в `site.analytics` JSON, затем `npm run build`.
- Реквизиты оператора ПДн (`site.operator`) — из карточки предприятия владельца (ИП Антонович Р. С.);
  `{{op:ogrn}}` сам подписывает ОГРН (13 цифр) или ОГРНИП (15), `{{op:email}}` — ссылкой.
- Статьи и документы: цены в статьях — только подстановкой `{{price:…}}` из каталога (check находит
  любую «от N ₽» не из JSON), реквизиты оператора — только `{{op:…}}`. Политика и Согласие — шаблон
  по 152-ФЗ, не юридическая консультация; Согласие — отдельный документ (`consent.html`).
  Клубная карта в «Больше, чем сервис» — ссылка на страницу оформления
  `https://admin.wahelp.cards/lendings/019c6b46-a042-7121-8e8c-23717fd3195e` (адрес от владельца, прямой
  ссылки на бота не ставим; check сверяет); «Обсудить условия» — отдельное действие (`data-membership`).
  Атрибуция 3D-модели (CC BY 4.0, Karol Miklas, «изменена») — строкой в панели гаража
  (`.garage__credit`), авторы фото студий — в подписи галереи «О нас»; страницы «Материалы» нет.
- Карты филиалов: вместо фото студии в каждой карточке «Локации» (главная и «О нас») — своя карта,
  iframe виджета карточки организации (`mapWidget` из JSON: `map-widget/v1/org/<slug>/<id>/?ll=…&z=16`,
  формат кода «Поделиться → Встроить»), `title` с названием и адресом. Создаёт его `maps.js` при
  подходе карточки к экрану; в разметке iframe и адреса виджета быть не должно (check). Размер
  области задан в CSS до загрузки (без скачков): на компьютере справа от текста, на телефоне — под
  ним. Ошибка и работа без JS — сообщение и «Открыть в Яндекс Картах ↗» внутри области; постоянной
  кнопки «На карте» в карточке нет. Окна карты больше нет: «На карте» в подвале ведёт к карте
  филиала (`{{locations}}#map-<id>`). Поверх углов iframe ничего не класть: там элементы управления
  и атрибуция Яндекса — плашки стоят по центру.
- Push в `main` сразу публикует сайт на GitHub Pages (`pages.yml`), его видит клиент (meatwash.ru — после ручной загрузки).
  В `main` не пушить — только ветка и pull request; сливает владелец.
- Единственная форма — «Заявка с фото» (`request.js`): отправка только на `site.requests.endpoint`
  (POST multipart, «Заявка отправлена» — только после ответа `{"ok": true}`); пока адреса нет —

- Запись — ссылками в yclients, у каждого филиала своя:

- Цены и факты — только из JSON (цены «от» в гараже тоже проверяются). Не выдумывать цифры,

## Проверки

```
npm run check          # ресурсы (src, srcset, CSS url), ссылки, якоря, цены и названия гаража,
                       # первый экран без сцены, 3D только через import() по нажатию,
                       # ссылки записи обоих филиалов; затем check:3d — бандл свежий,
                       # модели совпадают с отчётом, бюджеты, ракурсы работ
npm run optimize-3d    # после замены source/3d/porsche-930.glb или настроек сжатия
npm run bundle-3d      # после правки src/porsche3d
npm run build          # = catalog (каталог, превью, js/data.js из JSON) + content (статьи,
                       # Политика, Согласие, sitemap.xml) + pages (src/partials)
npm run content        # после правки src/content или site в JSON
npm run catalog        # после правки JSON или шаблона каталога
npm run pages          # после правки src/partials
npm start              # http://127.0.0.1:4173, открывать через file:// нельзя
```

Вёрстку проверять на всех страницах (главная, услуги, о нас, статьи, статья, документы): 320, 390, 430, 768, 1024, 1440, ноутбучной высоте (1366×657, 1280×720) и телефоне
в альбомной ориентации: без горизонтальной прокрутки (мерить `scrollWidth`), без наложений,
без ошибок в консоли; отдельно — `?motion=reduce`. Гараж — во всех состояниях (загрузка с медленной
сетью, готов, ошибка, нет WebGL), закрытие во время загрузки, повторные открытия (один canvas),
на телефоне — жесты и «Свернуть услуги»; закрытие, итог и «Записаться» в пределах экрана.
WebGL в headless Chromium без видеокарты — `--use-angle=swiftshader --enable-unsafe-swiftshader`
(медленно: кадр ~20 с), с видеокартой — CDP.
