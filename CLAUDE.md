# Meat Wash — правила проекта

Статический сайт сети детейлинг-студий Meat Wash (Мясницкая, Технопарк), три страницы:
главная (`index.html`: фото-витрина — одна машина в шести состояниях по прокрутке, GSAP
ScrollTrigger, 3D-режим «Оживить Porsche» только по нажатию, «Гараж услуг», превью услуг,
«До и после», клуб коротко, локации, «Больше, чем сервис»), `services.html` (каталог цен, запись) и `about.html`
(о клубе, фото, «Перед визитом», локации). Запись — во внешний yclients, карта — окно
с виджетом Яндекс Карт.
За основу взята версия https://meat-wash.vercel.app (действующий сайт клиента, его не трогаем),
поверх неё — наши исправления записи, доступности, мета и деплоя.
Эти правила дополняют глобальную web-команду (`~/.claude/agents/`) и важнее общих, где конкретнее.

## Устройство

- `dist/` — это и есть сайт: `index.html`, `services.html`, `about.html`, `credits.html`, `css/`,
  `js/`, `assets/`. Что генерируется (руками не править — править источник и перегенерировать):
  - общие части страниц — шапка с меню, подвал, окна записи и карты, `.mobile-cta`, карточки
    локаций, блок записи `#book`, клубный блок `#membership` (главная и «О нас») — живут в `src/partials/*.html` и вставляются между маркерами
    `<!-- SHARED:<имя>:START/END -->` скриптом `npm run pages` (`scripts/pages.mjs`; там же список,
    какая часть на какой странице, и подстановки `{{home}}`, `{{current:…}}`, `{{loc:<id>:<поле>}}`);
  - каталог на `services.html` (`CATALOG`), превью четырёх направлений на главной (`PREVIEW`)
    и `dist/js/data.js` (цены и филиалы для скриптов) — `npm run catalog` из JSON;
  - `npm run build` = catalog + pages. Результат коммитится; CI ничего не генерирует —
    `npm run check` падает, если страница разошлась с источником.
  Исходники со сборкой есть ещё у 3D-режима: `src/porsche3d/` → `dist/js/porsche3d.bundle.js`,
  `source/3d/` → `dist/assets/3d/`.
- Входы скриптов: главная — `main.js` (+ `vendor/gsap`, `ScrollTrigger`); внутренние — `page.js`
  (только общее: `ui.js`, `catalog.js`, шторки `proof.js` — если на странице есть `[data-ba]`).
  `ui.js` — общее всех страниц: меню, окна записи/услуги/карты, якоря (прямой заход на
  `services.html#price-*` раскрывает `details`), блокировка прокрутки (`html.is-locked`,
  `body.dialog-open`). `maps.js` — окно карты, грузится в простое после `load`; до этого «На карте» —
  обычная ссылка на карточку Яндекса. `body.js` — выбранный тип кузова (sessionStorage `mw:body`),
  общий для каталога и гаража. Стили всех страниц: `style.css` → `cinematic.css` → … → `pages.css`
  (страницы, превью, окно карты, действия локаций).
- `dist/js/main.js` — ScrollTrigger, загрузка витрины, статичный режим, состояние шапки;
  `stage.js` — фото-витрина (два слоя крест-накрест, шторка «до/после» для гаража);
  `config.js` — тексты глав, `LADDER` и `LADDER_AT` (кадр и его граница по прогрессу), работы
  гаража (`ZONES` с `price: {program}|{item}` — ссылка на цену каталога, `EXCLUSIVE`, `ZONE_SHOTS`,
  `SHOT_BASE`, `SHOT_FOCUS`); `configurator.js` — «Гараж услуг»;
  `proof.js` — шторки блока «До и после» (`#proof`, работают и в статичном режиме);
  `live3d.js` — кнопка «Оживить Porsche»,
  ракурсы, переключатель «Показать в 3D» в гараже (сама сцена — в бандле, см. ниже).
  `live3d.js` не входит в статический граф: `main.js` грузит его `import()` после `load`
  в простое и только после настоящей пробы `getContext('webgl2')` (результат — sessionStorage
  `p3d-webgl-ok` / `p3d-webgl-denied`); он сам подключает `css/porsche3d.css` и снимает `hidden`
  с кнопки. Проба в Worker через OffscreenCanvas не годится: там контекст создаётся и при
  выключенном WebGL страницы.
- Кадры витрины: `dist/assets/shots/cf-<id>.webp` (1600 px) и `cf-<id>-s.webp` (900 px, для
  `innerWidth ≤ 900`). Путь собирает `stage.js` из id — новый кадр кладём в обоих размерах,
  `npm run check` проверяет, что все id из `config.js` есть на диске.
- `dist/assets/meatwash-content.json` — единый источник цен, услуг, адресов, часов, ссылок записи
  и карт (org id, координаты `lat`/`lon` и `mapWidget` — из данных виджета Яндекса, 28.09.2026).
  Адреса и часы в нём — в том виде, в каком их показывает сайт; из JSON собираются карточки
  локаций, подвал, окна записи и карты, каталог, превью и `js/data.js` (гараж, окно услуги, карта).
- Стили: `style.css` (токены и база) → `cinematic.css` (сцена, статичный режим) → `stage.css`
  → `proof.css` → `configurator.css` → `catalog.css`. Место под ряд 3D (положение hero и
  `.hero-bar` на телефоне и в статичном режиме) — в конце `cinematic.css` под классом
  `html.p3d-capable` (ставит инлайн-скрипт в `<head>`, если есть WebGL 2; без него — как v2).
  Остальное — `porsche3d.css`, его подключает `live3d.js` (в `index.html` ссылки нет). Многие правила `style.css` перекрыты
  в `cinematic.css` — проверяй, где правило действует на самом деле.
- 3D-режим грузится **только по нажатию**: `live3d.js` делает `import('./porsche3d.bundle.js')`,
  бандл (three r180, GLTFLoader, декодер Meshopt — внутри, importmap не нужен) сам скачивает
  модель. До нажатия ни движок, ни модель, ни декодеры не запрашиваются. `npm run check`
  падает на статическом импорте бандла, `<script>`, preload/prefetch, ссылке на `.glb`,
  `assets/3d` или importmap в коде страницы; разрешён только `import()` строкой.
- Исходник модуля — `src/porsche3d/` (`index.js` — mount и камера, `views.js` — ракурсы,
  показ и работы гаража, `room.js` — помещение и свет, `models.js` — манифест моделей,
  создаётся скриптом). После правки: `npm run bundle-3d` и закоммитить бандл.
- Модели: `source/3d/porsche-930.glb` (исходник, в `dist` не публикуется) → `npm run optimize-3d`
  → `dist/assets/3d/porsche-930-{desktop,mobile}.<хеш>.glb` + `src/porsche3d/models.js` +
  `source/3d/optimize-report.json`, затем `npm run bundle-3d`. Имя с хешем содержимого —
  смена модели не ловит старый кэш. Руками GLB и `models.js` не править.
- `scripts/prune-deploy.mjs` при публикации убирает из копии `dist` то, что страница
  не запрашивает (ttf, логобук в PNG и других цветах, картинки прошлых версий макета).

## Ловушки

- Длина сцены — только `--scene-len` в `cinematic.css` (780svh компьютер, 400svh портрет ≤900,
  540svh низкий альбом). Доли глав (`STOPS`, `LADDER_AT`, окна глав в `main.js`, путь 3D) от неё
  не зависят — меняется скорость. Своих высот у `.scene` быть не должно (проверяет check);
  поворот держит `keepSceneProgress()`. Snap к главам выключен (на iOS с инерцией ощущается как
  залипание); `?snap=1` включает мягкий snap для проверки на устройстве.
- `./#garage` (тизер на services.html) открывает гараж на главной, когда витрина готова; хеш
  сразу убирается. В статичном режиме гаража нет — человек остаётся на первом экране.
- Витрина «готова», когда загрузился кадр текущего места прокрутки: только тогда
  `body.cfg-ready` и кнопка «Гараж услуг». Ошибка кадра или 25 с без него — статичный режим
  (`staticExperience()`), гаража нет.
- Статичный режим (`?motion=reduce`, системное «уменьшить движение», Save-Data, ошибка
  витрины): `state.progress` обнуляется, шапка считается только по прокрутке.
- Гараж открыт — `inert` на слоях сцены, фокус в `#cfg-panel`, при закрытии фокус на кнопку
  (`preventScroll`). Ушли прокруткой ниже сцены — панель закрывается сама. Esc при открытом
  `dialog` панель не трогает.
- Включённый 3D — фон всей сцены: камера и эффекты глав ведутся прокруткой, как в v1.0
  (`setProgress`, путь `SCROLL_STOPS` в `src/porsche3d/views.js`): 01 грязь смывается
  (шейдер лака `uClean`; на старте машина пыльная, как на фото hero), 02 стекло растворяется,
  виден кокпит (`interior.js` из v1), 03 риски полировки исчезают и по борту идёт свет,
  04 капли на капоте (`water.js`, transmission). Кадры витрины под canvas при этом не
  меняются (`live3d.covering`). На p≈0 — показ и ракурсы, начало прокрутки их останавливает.
  В статичном режиме и при «уменьшить движение» 3D — только первый экран (гаснет на 0.02–0.09).
- «Обычный вид» и закрытие гаража освобождают видеопамять (`dispose`); модель остаётся
  в памяти модуля — повторное включение без сети. «Обычный вид» не трогает прокрутку:
  никаких `scrollTo`, фокус только с `preventScroll`. В главах ряд скрыт — там кнопка
  `.p3d-float` под «Гаражом услуг».
- 3D не должен мешать прокрутке: колесо не слушаем, у canvas `touch-action: pan-y`, поворот
  касанием — только горизонтальный жест с порогом 8 px.
- Статичный режим 3D не выключает: без показа и параллакса, `staticExperience()` сбрасывает
  inline-стили `.hero-bar`. Без WebGL 2 ряд `.p3d` остаётся `hidden`. Если API нет — класс
  `p3d-capable` не ставится; если API есть, а проба не создала контекст — класс остаётся (место под
  ряд пустое: снять его после первой отрисовки значило бы сдвинуть hero).
- Гараж: `showService(id)` → ракурс и эффект работы (`SERVICE_FX`: мойки — смывание, полировка —
  риски, керамика — капли, салон — кокпит); `false` — фото. В 3D снимаем `has-pair`; «Показ»
  и «Ролик» гаража идут на фото, переключатель 3D на это время выключен.
- Модель выбирается по устройству (`pickQuality`): облегчённая — сенсор без мыши, память < 4 ГБ
  (Chrome округляет вниз) или Save-Data; узкое окно с мышью получает модель для компьютера.
- Каталог (`services.html`, маркеры CATALOG), превью (`index.html`, PREVIEW) и `js/data.js` генерирует
  `scripts/catalog.mjs` из JSON; общие части страниц — `scripts/pages.mjs` из `src/partials`.
  Правь шаблон, фрагмент или данные, затем `npm run build`. Ссылки внутри фрагментов — через
  подстановки (`{{home}}#locations` → `#locations` на главной и `./#locations` на остальных).
- Гараж: цены работ — ссылки на каталог (`price: {program: i}` или `{item: "название"}`),
  программы мойки взаимоисключающие (`EXCLUSIVE`: каждая следующая включает предыдущую),
  цена мойки — для выбранного кузова (`body.js`, общий выбор с каталогом). Check сверяет цену
  каждой работы и сумму каждого набора по всем четырём кузовам.
- Окно карты: iframe виджета (`map-widget/v1/org/<slug>/<id>/?ll=…&z=16` — формат кода
  «Поделиться → Встроить» карточки организации) создаёт `maps.js` только при открытии и только
  для выбранной студии, при закрытии удаляет. В разметке iframe и адреса виджета быть не должно
  (check). Поверх углов iframe ничего не класть: там элементы управления и атрибуция Яндекса.
- Push в `main` сразу публикует сайт на GitHub Pages (`pages.yml`), его видит клиент.
  В `main` не пушить — только ветка и pull request; сливает владелец.
- Форм сбора данных нет намеренно. Запись — ссылками в yclients, у каждого филиала своя:
  Мясницкая `n975571…/company/906067`, Технопарк `n1982508…/company/1743348`
  (общая `n975571.yclients.com` открывает только Мясницкую — на странице её быть не должно,
  это проверяет `npm run check`). Окно записи игнорирует клики первые 400 мс и второй клик
  двойного: иначе двойной клик закрывал окно или сам открывал Мясницкую.
  Предвыбор услуги в yclients (`?o=s<ID услуги>`) форма поддерживает (проверено 28.09.2026), но
  не используется: параметр недокументированный, «Трёхфазной» на Мясницкой нет, а цены программ
  на Мясницкой в yclients выше, чем в JSON. Решает владелец.
- Цены и факты — только из JSON (цены «от» в гараже тоже проверяются). Не выдумывать цифры,
  отзывы, клиентов, акции, программы лояльности.
- `canonical`, `og:url`, `og:image`, JSON-LD, `robots.txt`, `sitemap.xml` указывают на
  GitHub Pages (`paul1l.github.io/MeatWash-v3.0`). Если сайт переедет на другой адрес — менять все.
- На Windows `core.autocrlf=true`; `.gitattributes` держит текстовые файлы в LF.
- `stamp-assets.mjs` при публикации ставит `?v=` только к CSS, JS и относительным import.
  Кадры `assets/shots` адресуются без версии — это совпадает с preload кадра hero, который добавляет инлайн-скрипт в `<head>` (не при `?motion=reduce`, Save-Data и «уменьшить движение»).

## Внешний вид

Вид — как в версии Vercel: бордово-бежевые токены в начале `style.css`, горизонтальный логотип
в шапке, заголовки Arsenal SC, текст Arsenal (обе — шрифты брендбука; начертания 400 и 700,
промежуточных нет). Логобук «Стенки Бюро» (`dist/assets/brand/`, фирменный `#861A22`) — справка,
а не требование. Sloop Script не подключён (платный).

## Проверки

```
npm run check          # ресурсы (src, srcset, CSS url), ссылки, якоря, цены, кадры витрины,
                       # 3D только через import() по нажатию, ссылки записи обоих филиалов;
                       # затем check:3d — бандл свежий, модели совпадают с отчётом, бюджеты
npm run optimize-3d    # после замены source/3d/porsche-930.glb или настроек сжатия
npm run bundle-3d      # после правки src/porsche3d
npm run build          # = catalog (каталог, превью, js/data.js из JSON) + pages (src/partials)
npm run catalog        # после правки JSON или шаблона каталога
npm run pages          # после правки src/partials
npm start              # http://127.0.0.1:4173, открывать через file:// нельзя
```

Вёрстку проверять на всех трёх страницах: 320, 390, 430, 768, 1024, 1440, ноутбучной высоте (1366×657, 1280×720) и телефоне
в альбомной ориентации: без горизонтальной прокрутки (мерить `scrollWidth`), без наложений,
без ошибок в консоли; отдельно — статичный режим `?motion=reduce`. 3D-режим — во всех
состояниях ряда (обычный, загрузка, 3D, ошибка) и с открытым гаражом; WebGL в headless Chrome
работает на реальной видеокарте (CDP).
